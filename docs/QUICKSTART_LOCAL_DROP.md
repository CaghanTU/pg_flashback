# Quickstart: local DROP recovery

This is the supported product path for ordinary LOGGED PostgreSQL tables.

## 1. Prerequisites

- PostgreSQL 15–18
- `wal_level = logical`
- `shared_preload_libraries = 'pg_flashback'`
- Extension installed and `CREATE EXTENSION pg_flashback;`
- `pg_flashback` CLI on `PATH` (from the package `bin/pg_flashback`)

```bash
sudo install -m 0755 bin/pg_flashback /usr/local/bin/pg_flashback
```

## 2. Check the instance

```bash
export PGHOST=/var/run/postgresql   # or your socket/host
export PGPORT=5432
export PGDATABASE=appdb
export PGUSER=postgres

pg_flashback doctor
```

Doctor exits non-zero when something is broken and prints an action for each error.

## 3. Protect a table

```bash
psql -c "CREATE TABLE public.orders(
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  customer text NOT NULL,
  total numeric(12,2) NOT NULL
);"

pg_flashback protect public.orders
pg_flashback status public.orders
```

## 4. Accidental DROP

```bash
psql -c "INSERT INTO public.orders(customer, total) VALUES ('ada', 12.50);"
psql -c "DROP TABLE public.orders;"
```

## 5. Recover without copying an LSN

Interactive:

```bash
pg_flashback recover public.orders
# answer: y
```

Non-interactive:

```bash
pg_flashback recover public.orders --latest-drop --yes
```

Verify:

```bash
psql -c "SELECT * FROM public.orders ORDER BY id;"
pg_flashback status public.orders
```

## Notes

- Normal recover finds the newest safe DROP automatically.
- If a different table was created with the same name, recover refuses overwrite.
- Partitioned, foreign, temporary, UNLOGGED, and materialized-view targets are rejected.
- Backup-backed / large-database features are advanced/experimental and are not
  part of this quickstart.
